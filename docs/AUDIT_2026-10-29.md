| D2 | `emo/gwi.py` `compute_gwi` | Median/MAD from the whole sample: future days set today's threshold (look-ahead). Unusable for prospective detection. | High for 2.0 | GWI v2: causal rolling baseline (past window only). |

## 5. Improvements and new tools proposed (for PLAN 2.0)

1. **Response-loop event table** (new): one row per Atlantic hurricane event, columns per loop link (forecast skill, attention, decision/action dates, outcome), built from machine-readable public sources. This replaces hand-coded event files for the engine domain.
2. **GWI v2** (repair of D2–D4): causal, per-article seasonal baseline, Poisson-binomial, block-permutation null; tested only on data dated after its protocol commit.
3. **SMF v2** (replace D5): skill vs persistence per forecast product; DM with Holm.
4. **Loop-coupling test** (new): do events with earlier attention or better forecasts get faster action, after controlling for storm intensity and landfall region? This is the falsifiable "emergent mind" test (PLAN 2.0, H4).
5. **Learning test** (new): does the action lag shrink across seasons beyond what forecast improvement alone explains (H5)?
6. **Prospective registry** (extension of the forecast ledger): before each season, register predictions; score after it. The only route to repeated blind results.
7. **Power simulator** (new, generalising `analysis/he_calibration.py`): every protocol states its power from synthetic data before data are opened.
8. Pinned environment, pre-push hook, JSON results (D8, D9, D12).
